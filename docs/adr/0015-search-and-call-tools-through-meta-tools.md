# Search and call upstream tools through meta-tools

Search matches whitespace-separated query terms as case-insensitive substrings across the qualified tool name, connection display name, account display name, and description. Empty queries return the full authorized catalog. Searches of three terms or fewer require every term. For longer natural-language queries without an exact result, search progressively removes trailing terms but retains at least the first two, allowing task details after the service and operation without forcing a second call. Guidance therefore puts service and operation first and favors reuse of returned schemas.

The Gateway MCP exposes `search_tools`, `call_tool`, and the approval-annotated `call_tool_with_approval` instead of advertising every upstream tool through `tools/list`. MCP has no portable way to promote search results into dynamically callable tools, so search returns authorized tool names, schemas, and policy metadata while the call meta-tools perform policy enforcement and forwarding without server-side client sessions.

Connection managers see a built-in CoStack entry first in MCP Connections. It has Tools configuration only, without Accounts or upstream transport settings. Its policies apply globally to the three meta-tools and default to Allow to preserve existing behavior. Blocked meta-tools are omitted from discovery and rejected on invocation. Require Approval uses a client-native gateway prompt; clients without elicitation support and Service Accounts cannot invoke those meta-tools. Upstream Tool Policies still apply independently.

Tool descriptions explicitly explain discovery and execution so clients can find upstream capabilities without a user naming CoStack. The search description includes distinct connection display names from the Principal's authorized search results when the built-in search policy is Allow. Block and Require Approval do not load or advertise those names. Server initialization instructions explain the search-to-call workflow and the Principal's Approval Method. These hints improve discovery but do not guarantee that a client supplies them to its model or that the model follows them.
